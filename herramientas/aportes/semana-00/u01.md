## Glosario

**pensamiento computacional**: procesos de pensamiento para formular problemas y sus soluciones de modo que un agente procesador de información pueda ejecutarlas eficazmente.
**secuencia**: orden en que el ordenador ejecuta las instrucciones, de arriba hacia abajo; cambiar el orden cambia el resultado.
**expresión**: código simple que produce un valor, como `10 + 20` o `"Hola"`; varias expresiones forman una declaración.
**declaración**: instrucción formada por una o más expresiones, como `print('Hola')`; varias declaraciones forman un programa.
**anotación (comentario)**: texto que el intérprete ignora y que explica el código; se escribe con `#` o entre tres comillas.
**palabra reservada**: palabra con función predeterminada en Python (`if`, `for`, `global`) que no puede usarse como identificador.
**entorno virtual**: espacio independiente con su propia versión de Python y sus paquetes, aislado de otros proyectos.
**error de sintaxis**: error por romper las reglas del lenguaje; el código no llega a ejecutarse.
**error de tiempo de ejecución**: error en código correcto que aparece mientras se ejecuta, como `ValueError` o `ZeroDivisionError`.

P: ¿Qué ocurre al ejecutar print('Hello' + 10)?
A) Imprime Hello10
B) Imprime Hello 10
C) Se produce un TypeError
D) Se produce un SyntaxError
Correcta: C
Por qué: el operador + no puede combinar una cadena con un número, y el fallo ocurre al ejecutar.
Referencia: PDF semana 0, pág. 61

P: ¿Qué imprime print('Hello', 'World!', sep=',')?
A) Hello World!
B) Hello,World!
C) HelloWorld!
D) Hello, World!
Correcta: B
Por qué: sep reemplaza el espacio que la coma pone entre valores por la cadena indicada, aquí una coma sin espacios.
Referencia: PDF semana 0, pág. 64

P: ¿Cuál de estos es un error de tiempo de ejecución?
A) print('Hello) con la comilla sin cerrar
B) int('two') al convertir texto no numérico
C) Escribir 1st_variable como nombre de variable
D) Usar una barra invertida mal colocada
Correcta: B
Por qué: int('two') es código bien escrito que falla al ejecutarse con ValueError; los otros son errores de sintaxis.
Referencia: PDF semana 0, pág. 74

## Cheatsheet

print('Hola')  # imprime una cadena (comillas simples o dobles que coincidan)
print(10 + 7.5)  # imprime un valor o resultado numérico, sin comillas
print('Hola', 10)  # la coma separa con un espacio y admite tipos mezclados
print('Hola' + 'Mundo')  # une cadenas sin espacio; con un número da TypeError
print('Hola' * 3)  # repite la cadena: HolaHolaHola
print('Hola\nMundo')  # \n inserta un salto de línea
print('Hola', end='')  # no salta de línea al final
print('a', 'b', sep=',')  # cambia el separador entre valores: a,b
# comentario  # anotación de una línea, el intérprete la ignora
mi_variable = 5  # estilo serpiente para variables y funciones
conda create -n nombre python=3.8  # crea un entorno virtual (PDF; se escribe en la terminal)
conda activate nombre  # activa el entorno (PDF)
uv sync  # crea .venv e instala lo de pyproject.toml (ampliación, no está en el PDF)
uv run jupyter lab  # abre JupyterLab dentro del entorno (ampliación)
uv add paquete  # instala un paquete en el entorno (ampliación)

## Errores comunes

- Abrir una cadena con un tipo de comilla y cerrarla con otro o no cerrarla: error de sintaxis.
- Sumar una cadena y un número con `+`, o multiplicar dos cadenas: TypeError.
- Usar una palabra reservada (`global`, `class`) o un nombre con espacio o que empieza por número como identificador.
- Creer que si no hay error de sintaxis el programa no fallará: los datos del usuario pueden causar errores de ejecución.
- Copiar código del PDF con la traducción rota (`timesleep(5)`, `concrete-n`) en lugar del original (`time.sleep(5)`, `conda create -n`).
