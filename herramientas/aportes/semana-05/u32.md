## Glosario

**programación dinámica**: técnica de diseño que resuelve un problema a partir de una relación recursiva, guardando las respuestas de los subproblemas en una tabla para no recalcularlas.
**subproblemas superpuestos**: llamadas recursivas duplicadas que resuelven varias veces el mismo subproblema, como `fib1(3)` dentro de `fib1(5)`.
**memorización**: técnica de almacenar en una tabla (diccionario o lista) las respuestas ya calculadas para devolverlas directamente cuando se repite el subproblema.
**bottom-up (ascendente)**: enfoque que resuelve primero los casos pequeños y construye con ellos la respuesta del caso completo, normalmente con bucles.
**top-down (descendente)**: enfoque de dividir y vencer que parte del problema completo y lo descompone mediante llamadas recursivas.
**coeficiente binomial**: número C(n, k) que cumple C(n, k) = C(n-1, k-1) + C(n-1, k), con valor 1 cuando k = 0 o k = n.
**triángulo de Pascal**: matriz triangular de coeficientes binomiales donde cada valor es la suma de los dos que tiene encima.
**subestructura óptima**: propiedad por la cual la solución óptima del problema se construye con soluciones óptimas de sus subproblemas.

P: ¿Cómo se llama el problema de las llamadas recursivas duplicadas que aparece en `fib1(5)`?
A) Desbordamiento de pila
B) Subproblemas superpuestos
C) Recursión mutua
D) Ordenamiento inestable
Correcta: B
Por qué: `fib1(3)`, `fib1(2)` y `fib1(1)` se calculan varias veces dentro del mismo árbol de llamadas.
Referencia: PDF parte 1, pág. 13

P: ¿Qué hace `fib2(n)` cuando `n` ya está en el diccionario `F`?
A) Vuelve a calcular `fib2(n - 1) + fib2(n - 2)`
B) Lanza un error
C) Devuelve `F[n]` de inmediato
D) Reinicia el diccionario
Correcta: C
Por qué: si `n in F`, el subproblema ya se resolvió y se devuelve el valor guardado sin recalcular.
Referencia: PDF parte 1, pág. 24

P: En `fib3(F, n)`, ¿qué indica un valor `F[n] < 0`?
A) Que el término es negativo
B) Que el término aún no se ha calculado
C) Que `n` es mayor que 1
D) Que hay un error de entrada
Correcta: B
Por qué: los términos pendientes se inicializan con `-1`; si `F[n] < 0`, se hace la llamada recursiva y se guarda el resultado.
Referencia: PDF parte 1, pág. 26

P: ¿Cuál es la diferencia principal entre dividir y vencer y programación dinámica?
A) Dividir y vencer no usa recursión
B) La programación dinámica no puede resolver Fibonacci
C) La programación dinámica almacena los subproblemas y no los recalcula
D) Dividir y vencer siempre es más rápido
Correcta: C
Por qué: ambos usan relaciones recursivas, pero la programación dinámica guarda los resultados en una tabla para evitar cálculos repetidos.
Referencia: PDF parte 1, pág. 16

P: ¿Qué devuelve `bin2(5, 3)`, que construye el triángulo de Pascal con una tabla `B`?
A) 5
B) 6
C) 10
D) 15
Correcta: C
Por qué: C(5, 3) = 10; la celda `B[5][3]` es `B[4][2] + B[4][3]` = 6 + 4.
Referencia: PDF parte 1, págs. 30–31

P: Para `maximum_subarray([-2, 1, -3, 4, -1, 2, 1, -5, 4])`, ¿cuál es la suma máxima de elementos sucesivos?
A) 4
B) 6
C) 7
D) 9
Correcta: B
Por qué: el tramo `4, -1, 2, 1` suma 6 y ningún otro tramo consecutivo suma más.
Referencia: PDF parte 1, pág. 38

F = {0: 0, 1: 1}  # tabla de fib2 con los casos base
if n in F: return F[n]  # fib2: devuelve el valor ya calculado
F[n] = fib2(n - 1) + fib2(n - 2)  # fib2: calcula, guarda y devuelve
F = [0, 1] + [-1] * (N - 1)  # fib3: lista de largo N + 1 con -1 = no calculado
if F[n] < 0: F[n] = fib3(F, n - 1) + fib3(F, n - 2)  # fib3: calcular solo si falta
a, b = b, a + b  # fib4: avance ascendente con dos variables
bin1(n - 1, k - 1) + bin1(n - 1, k)  # bin1: recurrencia del coeficiente binomial
B = [[0] * (i + 1) for i in range(n + 1)]  # bin2: triángulo con n + 1 filas
B[i][j] = B[i - 1][j - 1] + B[i - 1][j]  # bin2: celda = suma de las dos de arriba
if j == 0 or j == i: B[i][j] = 1  # bin2: bordes del triángulo
for j in range(n, -1, -1): B[j] = B[j] + B[j - 1]  # bin3: una sola lista, de derecha a izquierda

## Errores comunes

- Creer que la recursión es lenta por sí misma: lo que cuesta es recalcular subproblemas superpuestos.
- Olvidar que la tabla `F` de `fib2` es global y se conserva entre llamadas; hay que reiniciarla para medir tiempos con justicia.
- Crear la lista de `fib3` con menos de `n + 1` posiciones y provocar un `IndexError`.
- Recorrer `bin3` de izquierda a derecha: sobrescribe valores de la fila anterior que aún se necesitan.
- Llamar a `bin1(n, k)` con `k > n` o `k < 0`: nunca alcanza el caso base.
- Inicializar el máximo del subarreglo en 0 cuando todos los números pueden ser negativos.
