## Glosario

- **búsqueda binaria**: algoritmo que busca un valor en una lista ordenada comparándolo con el elemento medio y descartando la mitad donde no puede estar.
- **espacio de búsqueda**: rango de índices, entre `low` y `high`, donde el valor buscado todavía podría encontrarse.
- **low / high / mid**: índice inferior, índice superior e índice medio, calculado como `(low + high) // 2`.
- **tiempo logarítmico**: complejidad O(log N); el número de operaciones crece muy despacio, una más cada vez que se duplica el tamaño de los datos.
- **lista ordenada**: requisito de la búsqueda binaria; los elementos están en orden ascendente.
- **huevos infinitos**: variante del problema de la caída de huevos en que se puede seguir experimentando aunque se rompan huevos, lo que permite usar búsqueda binaria.
- **operador //**: división entera; devuelve el cociente sin decimales, usado para calcular el elemento medio.

A) Tener elementos únicos
B) Estar ordenada
C) Tener tamaño par
D) Contener solo enteros positivos
Correcta: B
Por qué: solo con la lista ordenada se puede descartar una mitad tras comparar con el elemento medio.

P: En `S = [11, 17, 26, 28, 37, 45, 53, 59]` con `low = 0` y `high = 7`, ¿cuál es el valor de `mid`?
A) 3
B) 4
C) 7
D) 2
Correcta: A
Por qué: mid = (0 + 7) // 2 = 3 y S[3] es 28.
Referencia: PDF parte 2, pág. 22

P: Si `nums[mid] < x`, ¿qué se hace en la búsqueda binaria?
A) high = mid - 1
B) low = mid + 1
C) Se devuelve mid
D) Se devuelve -1
Correcta: B
Por qué: x solo puede estar a la derecha de mid, así que se descarta la mitad izquierda con low = mid + 1.
Referencia: PDF parte 2, pág. 23

P: ¿Cuántas comparaciones se realizan, como máximo, al buscar un valor en una lista ordenada de 8 elementos?
A) 1
B) 8
C) 3
D) 4
Correcta: D
Por qué: en el peor caso (por ejemplo, buscar 77) el PDF muestra cuatro operaciones, que corresponden a log2(8) + 1.
Referencia: PDF parte 2, pág. 35

P: ¿Cuál es la complejidad temporal de la búsqueda binaria en el peor caso?
A) O(n)
B) O(1)
C) O(log N)
D) O(n^2)
Correcta: C
Por qué: el espacio pasa de N a N/2, N/4, ... hasta 1, lo que ocurre tras log2(N) pasos.
Referencia: PDF parte 2, pág. 33

P: En `find_highest_safe_floor2`, ¿qué se devuelve al terminar el bucle?
A) low
B) high
C) mid
D) low - 1
Correcta: D
Por qué: al terminar, low es el primer piso donde se rompe el huevo; el piso más alto seguro es el anterior.
Referencia: PDF parte 2, pág. 43

## Cheatsheet

```python
low, high = 0, len(nums) - 1      # espacio de búsqueda inicial: toda la lista
while low <= high:                # mientras queden candidatos
mid = (low + high) // 2           # índice del elemento medio
if nums[mid] == x: return mid     # encontrado: devuelve la posición
elif nums[mid] > x: high = mid - 1  # x está a la izquierda: descarta la mitad derecha
else: low = mid + 1               # x está a la derecha: descarta la mitad izquierda
return -1                         # se agotó el espacio: x no existe
print(low, high, mid)             # traza para contar las repeticiones del bucle
sorted(nums)                      # ordena la lista antes de buscar
math.log2(n)                      # pasos máximos aproximados: log2 de n
low, high = 1, height             # huevos: pisos entre 1 y la altura
if do_experiment(mid, breaking): high = mid   # se rompe: la solución está en mid o debajo
else: low = mid + 1               # no se rompe: la solución está por encima
return low - 1                    # piso más alto seguro
```

## Errores comunes

- Aplicar la búsqueda binaria a una lista sin ordenar: puede descartar la mitad que contiene el valor.
- Usar `low < high` en lugar de `low <= high` al buscar un elemento: no se comprueba el último candidato (por ejemplo, adivinar el 100 en el cuestionario del PDF).
- Olvidar el `+ 1` o el `- 1` al mover `low` o `high`, lo que puede producir un bucle infinito.
- Devolver `low` en lugar de `low - 1` en el problema de los huevos.
- No contemplar que el huevo no se rompa en ningún piso (`breaking > height`): el código del PDF devuelve `height - 1` en ese caso.
